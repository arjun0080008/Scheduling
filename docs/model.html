The scheduling problem is a constrained assignment under partial information. Who is in clinic on a given date is stored nowhere — it is derived, and for much of the year the data it is derived from is genuinely undecided. The model makes that gap explicit rather than defaulting over it.

§1Objects and the block map

R is the set of residents, |R| = 40, split evenly by level ℓ : R → {PGY-1, PGY-2}. B = {1, …, 12} are the rotation blocks. D are the dates of the academic year Y = [2026-07-01, 2027-06-30] — 365 days holding 261 clinic weekdays. W = {1, …, 5} are Monday to Friday, and w(d) is the weekday of date d.

Each block is a closed date interval [sk, ek]. The twelve intervals are pairwise disjoint and contiguous, so they partition the year:

β : D → B ∪ {⊥},   β(d) = k  ⟺  sk ≤ d ≤ ek,   otherwise ⊥ (outside the year)
Length check  —  7 blocks of 28 days + 4 blocks of 35 days + 1 block of 29 days  =  196 + 140 + 29  =  365, exactly the span of Y. No gaps, no overlaps.

1.1  The rotation matrix and the elective-day map

Every resident holds one rotation per block, encoded as a letter — a total function, a dense 40 × 12 = 480-entry matrix supplied by the residency programme:

C : R × B → {O, N, E, A}
O outpatient — clinic every weekday of the block  ·  N inpatient / nights / ICU — no clinic  ·  E elective-type — exactly one clinic weekday per week  ·  A away rotation — as E, flagged for confirmation

Codes E and A fix the frequency — one day a week — but not which day. That is a second, independent datum, and critically a partial function, since the programme settles it only about a month ahead:

δ : R × B → W ∪ {⊥},   with δ(r, k) = ⊥ whenever the clinic day for that block is undecided
The domain of δ is entered by the scheduler and is empty on first use. No value of δ is ever inferred, defaulted or interpolated.

§2The availability function

Everything the application displays follows from one function. Writing k = β(d):

a(r, d) =
NONEif k = ⊥, or w(d) ∉ W, or r is inactive  (outside year, weekend, off roster) FULLif C[r, k] = O NONEif C[r, k] = N ELECTIVE_TBDif C[r, k] ∈ {E, A} and δ(r, k) = ⊥ ELECTIVE_DAYif C[r, k] ∈ {E, A} and w(d) = δ(r, k) NONEotherwise

The soundness property

Define the in-clinic predicate ι(r, d) = [ a(r, d) ∈ {FULL, ELECTIVE_DAY} ] and the roster R(d) = { r : ι(r, d) }. Because ⊥ maps to its own outcome instead of collapsing into a weekday, ι holds only where a human supplied the day. So R(d) is a lower bound on who is truly in clinic, never an over-estimate, and it is monotone in information: setting δ(r, k) = j adds r to exactly the dates of block k with weekday j, and removes them from none. Under-booking is recoverable; double-booking a resident who is on the wards is not.

§3Templates and horizon-dependent admissibility

A clinic day is not a bucket of appointments but an ordered sequence of typed slots:

T(ℓ, w) = ⟨ (mi, μi, ci) ⟩,   m = start minute, μ = duration, c ∈ {Est, New, FROZEN, HospFU, Any}
Invariant — no slot satisfies 720 ≤ m < 780. The lunch hour is structurally absent, not merely blocked. PGY-2 slots have μ = 30, PGY-1 slots μ = 60. Durations are never shortened to create room.

§4The constraint hierarchy

With b(r, d) the patients booked with r on d, and A attendings, four ceilings act at once — three per resident, one across the day:

Per resident   b ≤ κ(ℓ,w) = ⌊ ρ · τ(ℓ,w) ⌋  (advance bookings, ρ = 0.70)   ≤   τ(ℓ,w)  (target)   ≤   |T(ℓ,w)|  (hard maximum)
Across the day   Σr b(r,d) ≤ Σ(d) = A · p(w),  p = 32  (16 on Thursday)   ⟹   bookable(d) = min( Σr τ, Σ(d) )
The chain κ ≤ τ ≤ |T| holds for all six (ℓ, w) combinations under the shipped defaults; the reserve τ − κ is what pays for Frozen releases, hospital follow-ups and same-day flex.

§5State: the continuity partition

Each present resident carries a booked load split by continuity level — how tightly the patient is bound to that doctor. This partition is what makes a principled overflow decision possible:

b(r) = μr + πr + αr
μ  C1 — must see own doctor. Immovable.  ·  π  C2 — prefer own team. Movable to the firm partner only.  ·  α  C3 — any doctor. Freely movable.

A firm pairs one PGY-2 with one PGY-1 inside a named attending lane — the partial order that stages 4 and 5, and the whole call-out cascade, navigate.

§6The five-stage pipeline

6.1  Stage 2 in detail

Capping runs in two phases. The local phase brings each resident to their own target; the global phase then enforces supervision across the day.

(a) local   for each r: while b(r) > τ(r), remove one from α, else from π; never from μ.
A second loop enforces b(r) ≤ |T|; only here may μ be broken, and doing so raises a named warning.
(b) global   while Σr b(r) > Σ(d): draw from the first non-empty pass of ⟨(PGY-2, α), (PGY-1, α), (PGY-2, π), (PGY-1, π)⟩, victim = arg max b(r).
PGY-1 loads are protected ahead of PGY-2 — a deliberate policy choice: a PGY-1 has half the slots and a 60-minute teaching visit is the hardest thing in the day to re-place.

6.3  Cost

Each removal or placement re-filters and re-sorts the candidate pool, so with n = |R(d)| residents present, an excess X and a waiting queue Q, building a day costs O((X + |Q|) · n log n) with all loops explicitly bounded. Forward searches for a resident's next clinic date are capped at a 420-day scan, so they terminate inside the academic year by construction. The year heatmap evaluates a(r, d) once per resident per clinic weekday — 40 × 261 = 10,440 evaluations, each O(1) — which is why the whole year renders in a single pass with no caching.

What this is not

The pipeline is a greedy heuristic with an explicit, auditable priority order, not an optimiser. It does not compute a globally optimal assignment and makes no such claim. That is the intended trade: every decision it takes can be read back as one sentence in the move list and overruled by the scheduler, which matters more at a front desk than optimality.

§7The call-out cascade

When resident g is absent their load (μ, π, α) must be redistributed today. Define the spare capacity of p when allowed x over target:

c(p, x) = max( 0,  min( τp + x,  |Tp| ) − bp )
The overflow allowance x is itself clipped by the template maximum, so no relaxation can ever produce more patients than there are slots. Only one call site uses x > 0.

Conservation

No patient is created or lost by the cascade:

μ + π + α  =  placedmust + placedprefer + placedany  +  deferred to g's next dates  +  nurse list

This identity is asserted directly in acceptance test 7, so a redistribution that silently dropped a patient would fail the build.

§9Verification and honest limits

9.1  Executable specification

Nine acceptance tests run on every page load. They are the specification:

#Asserts
1block partition; friendly failure outside the year
2O / N / E / A resolve correctly across four blocks
3only outpatient residents appear before days are set
4Thursday AM only; Friday 09:00; lunch never used
5an empty window still returns nearest dates
6the 60 → 32 squeeze; PGY-1 protected
7cascade bound τ+2 and the conservation identity
8all 261 weekdays render with counts and names
9an undecided clinic day is never guessed or counted

9.2  What the model does not claim

  • The rotation matrix C is programme-supplied data. The tool cannot verify it and does not try.
  • δ is empty until entered. Coverage of the year is therefore a function of scheduler effort, not of the algorithm.
  • τ, ρ and p = 32 are policy parameters, not measured capacities. All are editable.
  • Because only counts are held, no true panel-level continuity rate can be computed — continuity is enforced prospectively, per booking.
  • Default firm pairing is by roster order and should be replaced with the real firm structure.
  • No optimality guarantee: §6 is a heuristic with a stated priority order.
